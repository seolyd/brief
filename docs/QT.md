# Daily QT 해석 쓰기

매일 아침 7시 전, Claude 예약 작업이 이 문서대로 그날 QT 해석을 씁니다. 앱의 **QT** 탭에서 읽고,
사용자는 그 아래에 마음에 남은 말씀, 나의 묵상, 나의 다짐, 기도를 적습니다.

## 순서

1. `git pull --rebase origin main`
2. `node scripts/qt-context.mjs` — 한국 시간 오늘 날짜로, 이달의 QT 항목마다 그날 본문을 절 번호와 함께 보여줍니다.
   맨 앞에 `ALREADY_DONE`이 있으면 한 줄만 남기고 끝냅니다.
3. 항목마다 해석을 써서 초안 JSON 하나에 모읍니다. 형식은 `scripts/save-qt.mjs` 맨 위 주석에 있습니다.
4. `node scripts/save-qt.mjs <초안.json>` — 검사를 통과하면 `public/data/qt/<날짜>.json`에 저장됩니다.
   걸리면 이유대로 고쳐서 다시 돌립니다.
5. 그 파일 하나만 커밋합니다. 메시지는 `QT YYYY-MM-DD`. main에 바로 푸시하고, 거절되면
   `git pull --rebase` 후 다시 푸시합니다.

## 항목마다 쓰는 것

| 칸 | 내용 |
| --- | --- |
| `title` | 그날 묵상 제목. 30자 이내. 본문의 표현을 살립니다. |
| `keyVerse` | 오늘의 한 구절. 반드시 그날 본문 안의 절 `[장, 절]`. 앱은 본문 파일에서 그 절을 그대로 꺼내 보여줍니다. |
| `interpretation` | 해석. 공백 빼고 250~900자 마크다운. 아래 구조를 따릅니다. |
| `questions` | 묵상 질문 2~3개. 본문에서 나온 질문 하나, 오늘 삶에 적용하는 질문 하나 이상. |
| `prayer` | 본문의 언어로 드리는 짧은 기도. 2~3문장. |

### 해석의 구조

1. **본문 흐름**: 이 본문이 무슨 이야기인지 두세 문장으로 정리합니다. 앞뒤 맥락이 필요하면 한 문장 덧붙입니다.
2. **붙잡을 말씀**: 핵심 구절이나 단어 한두 개를 짚고, 그 뜻을 풀어 줍니다. 배경 설명(역사·문화·원어)은
   널리 받아들여지는 것만 씁니다. 확실하지 않으면 쓰지 않습니다.
3. **오늘의 적용**: 이 말씀이 오늘 하루의 말, 일, 관계, 마음에 무엇을 요청하는지 구체적으로 씁니다.

단락은 짧게, 소제목이 필요하면 `###`까지만 씁니다. 본문을 따옴표로 인용할 때는 그날 본문의 개역한글 표현을
그대로 옮깁니다. 다른 성경 구절은 본문을 옮기지 말고 장절만 적습니다(예: 요 15:5 참고).

## 원칙

- **본문이 중심입니다.** 본문에 없는 말을 본문이 한 것처럼 쓰지 않습니다.
- **교파를 가르지 않습니다.** 세례 방식, 예정과 자유의지, 종말론의 세부, 은사 논쟁처럼 교회마다 다르게 가르치는
  주제는 단정하지 않습니다. 필요하면 "여러 해석이 있습니다" 정도로 둡니다.
- **약속을 과장하지 않습니다.** 믿으면 병이 낫거나 돈이 생긴다는 식의 보장, 두려움을 주는 경고, 특정 사람·집단에
  대한 정죄는 쓰지 않습니다.
- **시사와 정치를 끌어오지 않습니다.** 뉴스, 정당, 선거, 특정 인물을 예로 들지 않습니다.
- **링크와 HTML은 쓰지 않습니다.** 검사에서 걸립니다.
- **어조**: 차분하고 따뜻한 존댓말. 설교처럼 몰아붙이지 않고, 함께 읽는 사람의 말투로 씁니다.
- 같은 본문이 다음 달에 다시 나와도, 그날 새로 씁니다.

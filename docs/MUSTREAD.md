# Must Read 쓰는 법 (Biz.Brief · All.Brief)

이 문서는 브리프를 쓰는 Claude 세션이 따르는 지침입니다. 하루 두 번 예약 작업이 전용 세션을 깨우면,
그 세션이 이 문서대로 **두 편**을 써서 저장소에 올립니다. API 키는 쓰지 않습니다.

| 글 | 무엇 | 저장 파일 |
| --- | --- | --- |
| **Biz.Brief** | 동네 밀착형 작은 사업 (픽업·수거·배달, 방문 서비스, 긱·부업, 동네 가게 성공 사례, 해외 동네 사업) | `public/data/bizbrief-<판>.json` |
| **All.Brief** | 일반 뉴스 (정치, 사회, 국제, 과학·기술, 생활·문화) | `public/data/allbrief-<판>.json` |

- 아침판: 한국 시간 06:41 · 저녁판: 18:41
- 두 편은 다루는 영역이 겹치지 않게 씁니다. **두 편 모두 주가·지수·종목·투자 판단을 넣지 않습니다.**
  같은 사건이 둘 다에 걸치면 Biz는 그것이 만드는 사업 기회·위험을, All은 사건 자체와 사회적 의미를 씁니다.

## 순서

1. 최신 `main`을 받습니다 (`git pull --rebase origin main`). 06:30·18:30 GitHub Action이 `public/data/feed.json`을 갱신합니다.
   GitHub 예약 실행은 늦거나 빠질 때가 있습니다. 피드가 갱신되지 않았어도 **기다리지 말고** 바로 쓰세요.
   그때는 기사 목록이 오래됐으니 웹 검색 비중을 높여 오늘 소식을 직접 찾습니다.
2. **Biz.Brief**
   1. `node scripts/mustread-context.mjs <morning|evening>` — 첫 줄이 ALREADY_DONE이면 Biz는 건너뜁니다.
   2. 기사 목록을 출발점으로 **웹 검색과 웹 페이지 읽기로** 사실과 숫자를 확인합니다.
   3. 아래 Biz 구조로 마크다운 파일 하나에 씁니다 (저장소 밖 임시 경로).
   4. `node scripts/save-mustread.mjs <판> <파일>` — 검사에 걸리면 고쳐서 다시 저장합니다.
3. **All.Brief**
   1. `node scripts/mustread-context.mjs <판> all` — 첫 줄이 ALREADY_DONE이면 All은 건너뜁니다.
   2. 주요 일간지 헤드라인 목록을 출발점으로, 여러 신문이 함께 크게 다룬 사안을 고르고 웹 검색으로 확인합니다.
   3. 아래 All 구조로 씁니다.
   4. `node scripts/save-mustread.mjs <판> <파일> all`
4. 새로 저장한 json 파일만(한 개 또는 두 개) 커밋해 `main`에 올립니다.
   커밋 메시지: `Must Read (<판>) <YYYY-MM-DD>` (All만 있으면 `All.Brief (<판>) <YYYY-MM-DD>`).
   푸시가 거절되면 `git pull --rebase` 후 다시 올립니다.

## 쓰는 원칙

- **숫자**(지수, 등락률, 지표, 금액)는 이번에 검색하거나 읽은 페이지에서 확인한 것만 씁니다.
  확인하지 못한 숫자는 쓰지 않고, 필요하면 "확인하지 못했다"고 적습니다.
- **사실과 해석을 구분합니다.** 해석은 `**해석:**` 또는 `**제 판단:**`으로 시작하는 문단에만 씁니다.
- **출처**: 항목마다 끝에 `출처: [매체 – 기사 제목](https://...)`. 주소는 이번에 실제로 검색 결과로 보았거나
  열어 본 페이지, 또는 컨텍스트의 기사 목록에 있는 주소만 씁니다. 주소를 짐작해서 만들지 않습니다.
- **투자 권유를 하지 않습니다.** 주식·코인·부동산 매매를 권하지 않고, 사업 아이템도 "성공 보장"처럼 쓰지 않습니다.
- 자극적인 표현, 과장, 공포를 부추기는 말을 쓰지 않습니다. 차분하고 명료한 한국어 평서문.
- 분량은 Biz 6,000~9,000자, 항목 7~10개 (All은 아래). 마크다운만 씁니다 (HTML 태그 금지 — 앱이 글자로 보여줍니다).
- 표는 비교할 때만. 표 첫 열은 짧은 이름(아이템·지표)으로 둡니다.

## Biz.Brief 원칙

Biz.Brief는 **동네에서 돈을 버는 작은 사업**의 이야기입니다. 독자가 보고 싶은 것은
"브랜드가 무엇을 출시했나"나 "큰 회사가 기존 자산으로 사업을 넓혔나"가 아니라,
**소상공인·개인이 지역을 중심으로 소소하게 성공한 사례**입니다.
주가·지수·종목·코인 매매, 투자 유치 금액 같은 투자 이야기는 쓰지 않습니다.

**다룰 것 (우선순위 순)**
1. **픽업·수거·배달형 생활 서비스** — 세탁(런드리고처럼 수거·배송), 칼 갈이 수거(칼드처럼), 신발·가방 수선 수거, 이불·커튼 세탁,
   반찬·도시락 정기 배달, 분리수거·대형폐기물 수거, 짐 보관·이사 도움 같은 하이퍼로컬 서비스
2. **방문·출장 서비스** — 집 청소, 에어컨·세탁기 분해 청소, 방충망·실리콘 보수, 반려동물 방문 돌봄, 출장 세차, 출장 수리
3. **긱 이코노미·부업** — 배달·심부름 대행, 동네 줄서기·장보기 대행, 주말 플리마켓, 공유주방·공유창고를 이용한 1인 사업
4. **동네 가게의 성공 사례** — 작은 식당·카페·빵집·꽃집·세탁소·철물점이 메뉴·운영·단골 관리로 살아남거나 키운 이야기,
   지역 특산물로 만든 로컬 브랜드, 2호점·지역 프랜차이즈로 넓힌 개인 사장님
5. **해외 동네 사업 따라하기** — 미국·일본·유럽에서 소상공인이 하는 픽업·방문·구독 서비스 가운데 한국에 아직 덜 퍼진 것
6. **소상공인 지원사업·규제** — 소상공인시장진흥공단·지자체 지원, 로컬 크리에이터 사업, 영업 신고·인허가, 배달 수수료 정책

**쓰지 않을 것:** 대기업·유명 브랜드의 신제품 출시, 기존 브랜드·플랫폼이 가진 자산으로 사업을 넓힌 이야기,
투자 유치 소식, 순수 소프트웨어·앱 신제품(동네 사장님이 바로 쓰는 도구라면 예외), 거대 플랫폼의 정책 변화(소상공인 수수료처럼 직접 영향이 있으면 예외).

- 아이템마다 **무엇을 하나 → 누가 사나 → 어떻게 돈을 버나(건당·월 구독·객단가) → 확인된 숫자 → 우리 동네에서 하면**의 순서로 씁니다.
  '우리 동네에서 하면'에는 필요한 장비·인허가·초기 비용·하루 처리량 같은 현실적인 조건을 적습니다.
- **매출·수익 숫자는 출처를 붙이고, 사장님 본인 주장이면 "본인 공개 기준"이라고 밝힙니다.** 확인이 안 되면 쓰지 않습니다.
- "월 1,000만 원 보장", "누구나 쉽게" 같은 과장은 쓰지 않습니다. 실패 사례와 위험(초기 비용, 규제, 체력, 경쟁)도 함께 적습니다.
- 다단계, 도박성, 불법 소지가 있는 아이템(무허가 영업, 저작권 침해, 개인정보 판매 등)은 소개하지 않습니다.
- 출처: 컨텍스트의 '국내 동네 사업·소상공인'과 '해외 동네 사업·부업' 기사 목록이 출발점입니다. 목록에 맞는 기사가 적은 날이 많으므로
  **웹 검색을 적극적으로 씁니다.** 검색어 예: "수거 배달 서비스 창업", "세탁 수거 서비스 동네", "칼갈이 수거", "출장 청소 창업 사례",
  "사장님 성공 사례 지역", "로컬 크리에이터 지원사업", "소상공인 성공 사례 2호점", "pickup delivery small business local",
  "side hustle local service", "neighborhood business idea Japan".
- 분량은 한국어 6,000~9,000자.

### 오늘의 아이템 (가장 중요한 칸)

독자가 가장 좋아하는 칸입니다. **동네에서 할 수 있는 작은 사업 아이템을 짧은 카드로 10~14개** 모읍니다.
이 칸은 앱의 Biz.News 맨 위에 카드로 그대로 뜨므로 형식을 지킵니다.

```
## 오늘의 아이템
- **[분류] 아이템 이름** 무엇인지 한두 문장(누가, 어디서, 무엇을, 얼마에). 왜 돈이 되는지·우리 동네에서 하려면 무엇이 필요한지 한 문장. [매체 – 기사 제목](https://...)
```

- 한 줄 = 한 아이템. 줄 안에서 줄바꿈하지 않습니다. 아이템마다 출처 링크 하나.
- 분류는 다음 중 하나: `픽업·수거·배달` `방문·출장` `긱·부업` `동네 가게` `로컬 브랜드` `해외 동네 사업` `지원사업`.
  한 판에 최소 4가지 분류가 섞이게 고르고, `픽업·수거·배달`과 `방문·출장`을 합쳐 4개 이상 넣습니다.
- 고르는 기준: 사장님 한 명~몇 명이 지역에서 시작할 수 있고, '왜 동네 사람들이 돈을 내는지'가 한 문장으로 설명되는 것.
- 좋은 예:
  - 세탁물을 문 앞에서 수거해 세탁 후 배송(런드리고)
  - 무뎌진 칼을 택배·수거로 받아 갈아서 돌려보내기(칼드)
  - 지역 특산물 + 익숙한 외식 메뉴(당진 쌀·서해 수산물 초밥집)
  - 세탁 데이터로 동네 수요를 읽어 시즌 운영 바꾸기
- 웹 검색으로 찾을 곳: 네이버·다음 뉴스의 '사장님' 인터뷰, 지역 신문의 소상공인 기사, 소상공인시장진흥공단·지자체 보도자료,
  해외는 Entrepreneur·Inc.의 작은 사업 사례, Side Hustle School·Starter Story 팟캐스트 소개글.

## All.Brief 구조 (아침·저녁 공통)

시장·투자 이야기 없이, 오늘 세상에서 무슨 일이 있었는지를 차분히 정리하는 글입니다.
분야마다 2~3개, 전체 항목 7~10개. 분량은 한국어 5,000~8,000자.

```
# 🗞 All Brief — 아침   (저녁판은 "All Brief — 저녁")

(날짜 줄)

(도입 2문단: 오늘 신문들이 공통으로 크게 다룬 일은 무엇이고, 왜 그것이 중요한가)

## 오늘의 핵심 3가지
- **정치** 한 줄
- **국제** 한 줄
- **사회** 한 줄   (라벨은 그날에 맞게)

## 1. 정치
### ① 제목
(무슨 일이 있었나 → 쟁점이 무엇인가 → 신문마다 시각이 다르면 짧게 비교 → **왜 중요한가:** → 출처)
## 2. 사회
## 3. 국제
```
